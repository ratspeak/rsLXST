# API stability

rsLXST is experimental and remains below 1.0. Its three library packages are
source-distributed with `publish = false`; none is currently a stable SemVer
promise.

That does not make accidental breakage acceptable. `api-stability.json` lists
every package, and `api-baseline/*.txt` records the complete explicit public
surface generated by pinned `cargo-public-api` and rustdoc versions. CI rejects
unreviewed drift so an intentional change must arrive with its downstream,
version, changelog, and interop reasoning.

- `lxst-core` contains codec/profile, stream, signalling, and wire concepts.
- `lxst-rns` is the Reticulum Link binding and typed packet adapter.
- `lxst-telephony` currently exposes both useful service controls and extensive
  runtime/state-machine machinery.

All three are classified **experimental**. Future work may promote a small
facade while hiding orchestration internals, but this checkpoint does not move,
rename, hide, or change anything. Ratspeak voice integration and the Python
LXST compatibility suite must be migrated and green before any such boundary
change.

The canonical snapshot uses all features on `aarch64-apple-darwin` and omits
auto-derived, auto-trait, and blanket implementations. Android ABI and media
behavior remain protected by the existing target, package, and live interop
gates rather than treated as stable Rust API by this host snapshot.

```sh
cargo install cargo-public-api --version 0.52.0 --locked
rustup toolchain install nightly-2026-08-01 --profile minimal
python3 tools/check-api-baseline.py
```

Use `--update` only after reviewing and recording the compatibility impact.
